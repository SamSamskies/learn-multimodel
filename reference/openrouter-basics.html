OpenRouter Basics

One OpenAI-compatible endpoint. Many models. You still own routing decisions.

Endpoints

UseURL
Chat Completions (apps / Bridge) https://openrouter.ai/api/v1/chat/completions
OpenAI SDK baseURL https://openrouter.ai/api/v1
Cursor BYOK override https://openrouter.ai/api/v1/cursor
List models GET /api/v1/models

Auth

Authorization: Bearer sk-or-v1-...

Keys live at openrouter.ai/settings/keys. Credits are separate from Cursor Pro and OpenAI platform billing.

Model IDs

openrouter/free
openai/gpt-4o-mini
anthropic/claude-sonnet-4
google/gemini-2.5-flash

Prefer provider/model slugs from openrouter.ai/models. Router aliases like openrouter/free pick among matching models for you — log the returned model to see what ran. Some catalog entries use a ~ prefix — copy the exact string from the docs.

OpenAI SDK drop-in

import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
  defaultHeaders: {
    "HTTP-Referer": "https://your-site.example",
    "X-OpenRouter-Title": "your-app-name",
  },
});

Optional headers help rankings on OpenRouter; they are not required for a successful call.

Glossary seeds

Gateway
A service that accepts one client protocol and routes to many upstream model providers (OpenRouter, PPQ.ai).
Provider (OpenRouter sense)
The upstream that actually runs the model (OpenAI, Anthropic, Together, …). One model slug can be served by multiple providers.
Provider (Inference Bridge sense)
An adapter in the extension (openai, ollama, soon openrouter) that implements streamChat.

Inference Bridge mapping

Bridge’s OpenAI adapter posts to api.openai.com/v1/chat/completions. An OpenRouter adapter is the same shape with:

  • URL → https://openrouter.ai/api/v1/chat/completions
  • Key → OpenRouter key
  • Models → provider/model catalog (static list or GET /models)
