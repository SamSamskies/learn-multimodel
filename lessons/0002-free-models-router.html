Free Models Router vs :free

Zero-cost inference is a routing decision — not a model identity. Know which you asked for, and which actually answered.

In Lesson 1 you already called openrouter/free. That slug is not a model — it is OpenRouter’s Free Models Router: it filters free catalog entries that can handle your request, then picks one at random. Budget-conscious Phase 4 work starts here: explore cheaply, then pin when reproducibility matters.

Two ways to stay free

Slug shape What it does When to use it
openrouter/free Router: capability filter → random free model Exploration, demos, “any free answer is fine”
provider/model:free Free variant: pin one free catalog entry You need a known free model for compares / Bridge defaults
Mission link
Choosing with evidence means knowing what ran. The router hides selection; the response’s model field reveals it. Log requested vs returned every time — the same habit you will need when Inference Bridge routes across providers.

How the router decides

Per the official free-router guide:

Analyze Inspect the request for required capabilities (vision, tools, structured outputs, …).
Filter Keep only currently available free models that support those capabilities.
Pick Choose one at random from that filtered pool and forward the request.
Report Return the usual Chat Completions payload; model names the upstream that ran (often with a :free suffix). 
// Router — you don't choose the upstream
model: "openrouter/free"

// Pin — you do. Copy a live slug from the catalog or from a router response.
// Hardcoded :free ids go stale (today's free can be tomorrow's paid-only).
model: "some-provider/some-model:free"
Limits (from the docs) + catalog churn
Free models can have tighter rate limits, higher peak latency, and uneven availability. The router does not let you control which free model is selected — that is what :free on a specific slug is for. A :free slug can also disappear (404 “unavailable for free”) while the paid slug remains — treat free pins as ephemeral, not forever defaults.

Do this now

~10-minute win: see the router pick vs a pinned :free slug.

  1. From the repo root: npm run practice -- 2
  2. Read three completions: two via openrouter/free, then one that pins the slug the router just returned (so the pin stays live as free catalogs churn)
  3. Compare model requested vs model returned — router requests stay openrouter/free; the pin request should be a real catalog entry (often ending in :free)
  4. Optional: browse openrouter.ai/models and pin your own: npm run practice -- 2 --model some/slug:free

When those three lines make sense, you can explore models for free without confusing “router alias” with “model identity” — and without baking stale free slugs into Bridge defaults.
