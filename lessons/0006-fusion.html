Lesson 6 · ~20 minutes

Fusion Deliberation

One model answers. Fusion deliberates. Reach for it when being wrong costs more than a few extra completions.

You can survive outages and read the bill. The mission also asks for quality judgment — when one slug isn’t enough. OpenRouter’s answer is Fusion: a panel of models, a judge that compares (not merges), then a final answer.

The pipeline

  1. Your outer model decides whether to invoke openrouter:fusion.
  2. A panel answers in parallel (each with web search / fetch).
  3. A judge returns structured analysis: consensus, contradictions, unique insights, blind spots.
  4. The outer model writes the final answer from that analysis.

The judge does not majority-vote into one blob — it surfaces agreement and disagreement (Fusion docs). Deliberation is one level deep: panel/judge cannot recurse into Fusion again.

Bill = sum of the parts
Fusion charges for panel + judge + outer completions (and any web tools they use). Latency stacks the fan-out. Use it when quality matters; skip it for “one word: ok.”

Three entry points, one pipeline

Entry When
model: "openrouter/fusion" Drop-in alias — Quality defaults if you pass no plugin config
plugins: [{ id: "fusion", … }] Configure panel / judge / preset on any call (including the alias)
tools: [{ type: "openrouter:fusion" }] Most control — attach to your outer model; force with tool_choice: "required"

  "model": "openrouter/fusion",
  "plugins": [{

  }],
  "messages": [ … ]
}

// Or a curated preset — no model picking:
// "plugins": [{ "id": "fusion", "preset": "general-budget" }]

Presets: general-high, general-budget, general-fast (task + tier). Explicit analysis_models / model override a preset (docs).
