Lesson 3 · ~15 minutes

Read Cost and Latency

Quality without a bill is half a decision. Every completion already tells you tokens, credits, and (if you time it) latency.

Your mission success criteria include reading cost and latency signals on each call — the same evidence habit as Phase 3 evals, applied to gateway routing. You already log returned model (Lesson 2). Now read the rest of the receipt.

Usage is always there

Per OpenRouter’s Usage Accounting guide, every Chat Completions response includes a usage object — no extra request flag. Older usage: { include: true } options are deprecated and ignored; details arrive by default (including on the final streaming chunk).

Field Meaning
prompt_tokens / completion_tokens / total_tokens Counts from the model’s native tokenizer (what pricing uses).
cost Credits charged to your OpenRouter account for this call.
cost_details Optional breakdown (e.g. upstream inference). Most useful for BYOK later.
*_tokens_details Optional: cached tokens, reasoning tokens, etc. when the model exposes them. 
// Shape from OpenRouter docs (fields may be omitted when zero / N/A)
usage: {
  prompt_tokens: 194,
  completion_tokens: 2,
  total_tokens: 196,
  cost: 0.000014,           // ← your bill for this call
  cost_details: { … },
  prompt_tokens_details: { cached_tokens: 0, … },
  completion_tokens_details: { reasoning_tokens: 0, … }
}
SDK typing caveat
The official OpenAI SDK types usage as the standard token trio. OpenRouter’s cost is still on the live JSON — log completion.usage (or cast) and look for cost, don’t assume TypeScript knows it.

Latency is yours to measure

OpenRouter does not put wall-clock latency in the Chat Completions body. Time the call yourself (performance.now() around chat.completions.create). For richer post-hoc stats (including provider-side timings), query GET /api/v1/generation with the completion’s id.

Mission link
Before you reach for Fusion (cost = sum of panel + judge completions), you need this habit: every call logs model, tokens, usage.cost, and latency_ms. That is the plumbing Inference Bridge will need to surface “why this model?” without vibes.

Do this now

~10-minute win: see $0 free vs a tiny paid cost side by side.

  1. From the repo root: npm run practice -- 3
  2. Compare two completions: openrouter/free vs openai/gpt-4o-mini (tiny prompt)
  3. Confirm free cost is 0 (or effectively free) and paid cost is a small positive number
  4. Note latency_ms for both — free is often slower or spikier; that is data, not a bug
  5. Optional: swap the paid slug — npm run practice -- 3 --model google/gemini-2.5-flash

When you can point at cost and latency_ms without opening the dashboard, you have the measurement loop for multi-model product decisions.
