Lesson 7 · ~20 minutes

Pareto Code Router

Don’t pin a forever coding slug. Set a quality floor; let OpenRouter pick the cheapest model that clears it.

You already met a capability-aware free lottery, explicit model fallbacks, and Fusion deliberation. For day-to-day coding, OpenRouter’s Pareto Router answers a different question: “strong enough coder, without overspending.”

One knob: min_coding_score

Call model: "openrouter/pareto-code" and optionally pass the pareto-router plugin with a score from 0 to 1 (docs). The score maps to an Artificial Analysis coding percentile tier — not an absolute IQ number. As the field moves, “top of the field” stays relative.

min_coding_score Tier Meaning
>= 0.66 (or omitted) high Top of AA’s coding field (default)
>= 0.33, < 0.66 medium Strong modern flagships below the tip
< 0.33 low Capable coders still above AA’s median
Pareto, not random
Within the tier: cheapest available model (or fastest p50 with openrouter/pareto-code:nitro). Plus up to two same-tier fallbacks for transient errors — not load balancing across the shortlist.

openrouter/free models[] pareto-code

Coding only + bill the winner
The router adds no fee; you pay the underlying model. High tier can resolve to expensive frontier coders. For fixed benchmarks, pin a slug — don’t use Pareto as your eval target. See limitations.

Session stickiness

Multi-turn coding hates mid-thread model switches (style drift, cold cache). Pareto pins model + provider for the conversation: automatic fingerprinting after cache hits, or set session_id so stickiness starts on the first success (docs). Cache expires after ~5 minutes idle.
