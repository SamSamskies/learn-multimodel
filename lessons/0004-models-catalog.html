Lesson 4 · ~15 minutes

Query the Models Catalog

A model picker is not a hardcoded list. It is a filtered view of a live catalog — with price and capability before you call.

Lessons 1–3 taught you to call and measure. Inference Bridge still needs a way to discover what you can call. OpenRouter’s answer is GET /api/v1/models — the same data behind openrouter.ai/models, shaped for apps.

What you get back

Each item is a Model object. For a Bridge-style picker you care about a handful of fields (full schema in the Models guide):

Field Why it matters
id Slug you pass as model on Chat Completions.
name Human label for UI.
pricing USD per token (strings). "0" means free for that dimension.
context_length Max context window (tokens).
supported_parameters What the API accepts (tools, structured_outputs, …).
architecture Input/output modalities — vision vs text-only. 
GET https://openrouter.ai/api/v1/models
Authorization: Bearer sk-or-v1-…

// Response (shape abbreviated)
{
  "data": [ { "id": "…", "name": "…", "pricing": { "prompt": "0", "completion": "0", … }, … } ],
  "total_count": 150,
  "links": { "next": null }   // or a next-page URL when you paginate
}
Pricing units
Catalog pricing.prompt / completion are per token (USD strings). Multiply by 1e6 to display familiar “$/M tokens”. That is list price — Lesson 3’s usage.cost is what you were actually billed for a call.

Filter and sort on the server

Prefer query params over downloading everything and filtering locally (per the docs):

Param Example use
sort pricing-low-to-high, latency-low-to-high, newest, …
supported_parameters tools — models that accept function calling
max_price Cap prompt price in $/M tokens (e.g. 0 for free-tier list)
q Free-text search by name or slug
output_modalities Default is text; use all or image when needed
Mission link
Inference Bridge’s OpenRouter adapter should not ship a stale slug list. Pull (or cache) GET /models, show id + price + capabilities, then let the user pick — the same “evidence before vibes” habit as Phase 3 evals.
