Provider Prefs and Fallbacks

One model slug is not one server. Reliability is two layers: failover across providers, then fallback across models.

You can discover a slug and measure a call. Inference Bridge also needs the call to survive upstream hiccups. OpenRouter does that in two layers — documented in Provider Routing and Model Fallbacks.

Two layers, two failure modes

Provider failover Model fallbacks
What it recovers Outage / 429 on the host serving this model Whole model down, context-length errors, moderation refusals
Default On (allow_fallbacks: true) Off until you set a models array
What changes Upstream provider (same model id) Which model answers
You configure provider object models (priority list)
Don’t conflate the glossary
OpenRouter provider = upstream that runs the model (OpenAI, Together, …). Inference Bridge provider = adapter in the extension. Same word, different layer — see OpenRouter Basics.

Shape the provider pool

Put a provider object on the Chat Completions body (docs). Defaults load-balance for uptime + price. Setting order or sort disables that load balancing and tries providers in a fixed sequence.

Field Use when…
order Try these provider slugs first, in this order
only / ignore Allow-list or block-list endpoints
allow_fallbacks false = hard-stop on your picks (compliance / BYOK); default true
sort "price", "latency", or "throughput" (no LB) 
// JSON body (OpenAI SDK: pass via cast — types omit OpenRouter fields)
{
  "model": "openai/gpt-4o-mini",
  "provider": {
    "sort": "latency",
    "ignore": ["deepinfra"],
    "allow_fallbacks": true
  },
  "messages": [ … ]
}

// Shortcuts on the slug (same as provider.sort):
//   model: "…:nitro"  → sort throughput
//   model: "…:floor"  → sort price

Narrowing with only / ignore / order trades control for recovery options — fewer eligible hosts means fewer places to fail over (reliability guide).

Opt in to model fallbacks

When every provider for the primary model fails (or the model itself refuses), walk a second list: 

{
  "model": "openai/gpt-4o-mini",
  "models": ["google/gemini-2.5-flash"],   // tried in order if primary errors
  "messages": [ … ]
}

Put a reliable cheap “floor” model last. You’re billed for the model that actually ran — check returned model. With the OpenAI JS SDK, pass provider / models on the create call (cast past types); Python docs use extra_body (Model Fallbacks).

Mission link
Bridge’s OpenRouter adapter should expose provider prefs and a fallback list — not just a single slug. Audit who served you with GET /api/v1/generation?id=… → provider_name (Lesson 3’s audit URL, now with a name on it).
