Your First OpenRouter Call

One vendor API is a dependency. A gateway is a choice surface — and Phase 4 is about choosing with evidence.

Your mission is to ship multi-model products — starting with Inference Bridge — without hardcoding your career to a single provider. OpenRouter is the on-ramp: one OpenAI-compatible API, hundreds of models, pay-per-token credits.

What OpenRouter is (and isn’t)

Thing Role You pay
OpenAI Platform First-party models + APIs OpenAI API credits
Cursor Pro Editor agent product Subscription / included usage
OpenRouter Multi-model gateway OpenRouter credits
Ollama (LocalLab) Local inference Your machine, not a gateway bill
Separate bills
Cursor Pro does not fund OpenRouter. OpenAI platform credits do not fund OpenRouter. You need an openrouter.ai account and a small credit balance for this lesson.

OpenRouter speaks the familiar Chat Completions shape. That matters for Bridge: your existing OpenAI provider already streams /v1/chat/completions — OpenRouter is mostly a different baseURL, key, and provider/model slug.

Setup (one time)

Step 1 Create an account at openrouter.ai.
Step 2 Add a small credit balance (a few dollars is enough for weeks of practice). Set a spend limit if the UI offers one.
Step 3 Create a key at Settings → Keys. It should start with sk-or-.
Step 4 In this repo, copy .env.example → .env and paste the key as OPENROUTER_API_KEY. 
cp .env.example .env
# edit .env:
OPENROUTER_API_KEY=sk-or-v1-...

The call

Point the official OpenAI SDK at OpenRouter. Same client, different host — documented in the OpenRouter quickstart. 

import "dotenv/config";
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
  defaultHeaders: {
    "HTTP-Referer": "https://github.com/SamSamskies/learn-multimodel",
    "X-OpenRouter-Title": "learn-multimodel",
  },
});

const completion = await client.chat.completions.create({
  model: "openai/gpt-4o-mini",
  messages: [
    { role: "user", content: "Say hello in exactly five words." },
  ],
});

console.log(completion.choices[0].message.content);
console.log(completion.usage);
console.log(completion.model);

Notice the model id: openai/gpt-4o-mini — provider/model, not a bare OpenAI name. Browse live slugs and prices on openrouter.ai/models.

Why this maps to Bridge
Inference Bridge’s OpenAI adapter posts to https://api.openai.com/v1/chat/completions. An OpenRouter adapter is the same streaming loop with https://openrouter.ai/api/v1/chat/completions, an OpenRouter key, and provider/model ids. Keep the OpenRouter Basics reference open when you wire that provider later.

Read what came back

Field What to notice
choices[0].message.content The assistant text — same Chat Completions shape as OpenAI.
model May differ slightly from what you requested (routing / aliases). Log both.
usage Token counts — your unit economics. Habit from Phase 3: measure, don’t guess.
id Request id for debugging in the OpenRouter activity/credits UI.

Do this now

~10-minute win: a real OpenRouter completion from this machine.

  1. At the repo root: npm install
  2. Copy .env.example → .env and set OPENROUTER_API_KEY
  3. Run npm run practice -- 1 (or node practice/0001-hello.mjs)
  4. Confirm five words of greeting, a usage object, and a returned model (default slug is openrouter/free — a free-models router; the returned model names which upstream was chosen)
  5. Optional: pin a specific slug — npm run practice -- 1 --model openai/gpt-4o-mini (or set OPENROUTER_MODEL in .env)

When that works, you have the integration shape Inference Bridge needs for an OpenRouter provider — before we touch the extension code.
